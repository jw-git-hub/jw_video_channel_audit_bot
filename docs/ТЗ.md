# ТЗ: @jw_video_channel_audit_bot

Аудит видеоканала: присылаешь ссылку на YouTube-канал — получаешь отчёт словами о том, как часто выходят видео, как
их смотрят, какие они и куда описания ведут зрителя.

Версия 1 · 27.09.2026 · **статус: утверждено владельцем 27.09.2026, после независимой проверки агентом-архитектором
(23 находки, учтены). План реализации — `docs/план.md`**

Репозиторий публичный. Адрес сервера, пользователь и пути здесь не пишутся — они в `deploy/deploy.local.env`
на Маке (раздел 14).

---

## 1. Цель и границы

@jw_video_channel_audit_bot — второй бот экосистемы `>jw_`, который приводит заказы. Его задача — продать пакет
«Канал на автопилоте»: Telegram-канал, который наполняется сам, в том числе новыми видео с YouTube. Заказчик —
владелец малого бизнеса с YouTube-каналом. Блогеры — не наш заказчик: этот рынок занят, аудит для них не делаем.

Бот делает:

- по ссылке на канал, @имени или ссылке на любое видео канала находит канал через YouTube Data API;
- считает четыре вещи — ритм, отдачу, форматы и куда описания ведут зрителя;
- пишет отчёт словами, на русском или английском, в одном сообщении-статье;
- в конце, если видео выходят, разворачивает на пакет и ведёт в личку разработчика одной кнопкой;
- считает людей и аудиты по меткам источника.

Бот не делает:

- не советует по роликам, заголовкам и превью; не говорит о CTR и удержании — их нет в открытых данных;
- не ставит каналу оценок («хорошо», «плохо», баллы) — это запрещённая без поправки Google «оценка канала» (раздел 11);
- не сравнивает каналы между собой и не копит данные разных каналов в общую статистику (раздел 11);
- не открывает присланные ссылки и ссылки из описаний: разбирает их в ID и ходит только в Google API и Telegram
  (раздел 10);
- не пишет текст моделью — только шаблоны, как чекер;
- не работает в группах;
- не трогает имя, описания, аватар и обложку бота: `setMyName`, `setMyDescription`, `setMyShortDescription`,
  `setMyProfilePhoto` в коде не вызываются. Профиль поставлен один раз 26.09.2026 (раздел 21).

Главная метрика — сколько людей написали в личку из отчёта. Нажатие кнопки бот не видит (Р5), поэтому считаются
сообщения «Пришёл из аудита канала: @имя» в личке. Кто и когда смотрел этот канал, показывает команда владельца
`/channel` (раздел 8).

## 3. Как это выглядит для человека

1. «Старт» — приветствие: что бот делает, что прислать, и абзац «Присылая ссылку, вы принимаете условия YouTube
   и мою политику данных» со ссылками.
2. Человек присылает ссылку на канал, @имя или ссылку на любое видео канала.
3. Бот сразу отвечает «Смотрю канал…» — статьёй с полосой.
4. Через несколько секунд это же сообщение превращается в отчёт. Пять сообщений подряд бот не шлёт.
5. В отчёте: название канала со ссылкой; четыре блока фактов; вывод с предложением пакета — если видео выходят;
   подпись о данных; кнопки «Обсудить с разработчиком», «Проверить другой канал», «Канал».
6. Не вышло — объяснение по-человечески: это не YouTube; не нашёл канал; старый адрес /c/ не нашёлся; данные
   YouTube сейчас недоступны; сейчас много проверок (раздел 7.4).

До запуска (`OPEN_TO_ALL=false`) всем, кроме владельца, `/start` показывает приветствие целиком — со строкой
согласия и ссылками, — а ниже «Бот скоро откроется»; на остальные сообщения — только «Бот скоро откроется». Человек
записывается с меткой источника. Так согласие видят и те, кого соберут метками до запуска.

## 4. Приём ссылки

| № | Правило |
|---|---|
| В1 | Ищем сначала в сущностях Telegram `url` и `text_link`, иначе — в тексте: первая ссылка на YouTube или первое `@имя`. Текст длиннее 2000 знаков — «не похоже на канал» |
| В2 | Хосты YouTube: `youtube.com`, `www.youtube.com`, `m.youtube.com`, `music.youtube.com`, `youtu.be`; `studio.youtube.com` — только `/channel/UC…` (владелец канала часто копирует адрес из Студии). Схема не обязательна. Регистр хоста не важен. Процентные коды в пути раскрываются один раз: `@%D0%BA…` → `@к…` |
| В3 | Что понимаем: `/@имя` → по имени (`forHandle`); `/channel/UC…` → по ID (`id`); `/user/ИМЯ` → старое имя (`forUsername`); `/c/ИМЯ` → по имени (`forHandle`), не нашлось — ответ `legacy_not_found`; `/ИМЯ` → по имени, не нашлось — старое имя (`forUsername`, ещё 1 единица), не нашлось — `legacy_not_found`; `/watch?v=ID`, `/shorts/ID`, `/live/ID`, `/embed/ID`, `youtu.be/ID` → видео, канал берём из него. `/ИМЯ` — только если это единственный сегмент пути и не служебное слово YouTube (`feed`, `results`, `playlist`, `account`, `premium`, `gaming`, `hashtag` и другие — список в коде). Хвост пути (`/videos`, `/featured`) и параметры, кроме `v`, отбрасываем |
| В4 | Проверка до сети: ID канала — `UC` и 22 знака `[0-9A-Za-z_-]`; ID видео — 11 знаков `[0-9A-Za-z_-]`; имя — 3–30 знаков: буквы любых алфавитов, цифры, `_`, `-`, `.`, `·`; старое имя — латиница и цифры. Не подошло — «не похоже на канал». Точные правила имени уточняются на разведке (раздел 21) |
| В5 | Слово без `@` и без ссылки — не ищем: «привет» не должен превращаться в чужой канал @привет. Ответ — «не похоже на канал» с примером |
| В6 | Ссылка не на YouTube — «это не YouTube», с примером. Ссылка на плейлист без `v` — «пришлите ссылку на канал или на видео» |
| В7 | Фото, голос, стикеры и прочее не текстом — «Пришлите ссылку текстом» |
| В8 | Пока идёт аудит человека, новая ссылка от него — «Сначала закончу с этим каналом» |
| В9 | Присланную ссылку бот не открывает: в Google уходят только ID, имя или старое имя, прошедшие В4, — параметрами запроса к постоянному адресу `https://www.googleapis.com/youtube/v3/…` |
| В10 | Канал, найденный по имени из `/c/ИМЯ` или `/ИМЯ`, может оказаться чужим: старые адреса и @имена — разные имена. Под ссылкой на канал в отчёте — строка `found_by_name` (7.4) |

## 5. Данные

### 5.1 Цепочка вызовов

Ключ — в заголовке `X-goog-api-key`, не в адресе: адрес попадает в тексты ошибок. Если YouTube Data API заголовок
не примет (проверка на разведке) — параметр `key` и маскировка в логах (Сек7). Каждый запрос — с `fields`, только
нужные поля: квоту это не экономит, но ответ в разы меньше.

| Шаг | Запрос | Единиц квоты | Что берём |
|---|---|---|---|
| 1 | только для ссылки на видео: `videos.list`, `part=snippet`, `id=<ID видео>` | 1 | `snippet.channelId` |
| 2 | `channels.list`, `part=snippet,contentDetails`, одно из `forHandle`, `forUsername`, `id` | 1 (для `/ИМЯ` — до 2) | ID канала, название, `customUrl` (@имя), описание, плейлист загрузок `contentDetails.relatedPlaylists.uploads` |
| 3 | `playlistItems.list`, `part=contentDetails`, плейлист загрузок, `maxResults=50`, по страницам | 1 за страницу | ID видео и дата выхода `videoPublishedAt` |
| 4 | `videos.list`, `part=snippet,contentDetails,statistics,liveStreamingDetails`, до 50 ID за раз | 1 за 50 видео | дата выхода, название, описание, `liveBroadcastContent`, длительность, просмотры, признак эфира |

- `fields` у `playlistItems.list` обязательно включает `nextPageToken`: без него листание молча остановится на
  первой странице. Тест — листание идёт, пока токен есть. Все четыре выражения `fields` проверяются на разведке.
- Страницы шага 3 идут, пока не наберётся 200 видео (`MAX_VIDEOS = 200`) или не кончатся видео за последние
  12 месяцев (6.2). После границы в 12 месяцев — ещё одна страница, если до 200 видео есть место: порядок
  плейлиста не документирован, видео сортируются по дате у нас.
- ID плейлиста загрузок берём из `relatedPlaylists.uploads`, а не заменой `UC` на `UU`: так записано в документации.
  Скрытые плейлисты `UUSH`, `UULF` не используем: правила запрещают недокументированные способы (III.D.7).
- Если на разведке в плейлисте загрузок найдутся видео «по ссылке» — к шагу 4 добавляется `part=status` (цена та же)
  и считаются только `public`.
- Описания видео нужны только для ссылок (6.4): ссылки вынимаются сразу, сами описания дальше не хранятся.
- Расход: обычно 3–6 единиц на аудит, самое большее — 10: два запроса, чтобы найти канал (видео по ссылке и канал
  или два поиска для `/ИМЯ`), четыре страницы и четыре пачки по 50. Квота по умолчанию — 10 000 единиц в сутки; свой потолок — 8 000 (Л9). Фактический расход —
  на разведке.
- Каждый запрос считается у нас, в том числе ответ с ошибкой — он тоже стоит единицу. Единицы за сутки по
  тихоокеанскому времени видны владельцу в `/stats`.

### 5.2 Кэш

- Два кэша на сутки, в памяти: «что прислали → ID канала» и «ID канала → факты отчёта». Повторный аудит того же
  канала за сутки не тратит квоту.
- Ключ «что прислали»: @имя и старое имя — без учёта регистра, ID канала и видео — с учётом.
- «Факты отчёта» — готовые итоги 6.1–6.6: числа, даты, название и ID лучших видео, итоги по ссылкам; дата сбора —
  это «сегодня» для этих фактов. Списка видео и описаний в кэше нет.
- Кэш держит до 500 каналов; старые вытесняются. При перезапуске кэш пуст — это нормально.
- В базу кэш не пишется (раздел 12).
- В отчёте — дата, на которую собраны данные (7.1): данные из кэша могут быть вчерашними.

### 5.3 Сроки и ошибки

- Срок одного запроса — 10 секунд, аудита целиком — 30 секунд, вместе с ожиданием места (Л1). Переадресации не
  проходим, прокси из окружения не берём, ответ больше 5 МБ не читаем.
- Порядок разбора ответа: сначала `error.errors[0].reason` Google, затем HTTP-статус.

| Ответ Google | Код в базе | Списание (Л5) | Сообщение (7.4) |
|---|---|---|---|
| `channels.list` без `items`; 404 `channelNotFound` | `not_found` | да | не нашёл такой канал |
| то же для `/c/ИМЯ` и `/ИМЯ` | `legacy_not_found` | да | старый адрес не нашёлся — пришлите @имя или ссылку на видео |
| `videos.list` по ссылке без `items` | `video_not_found` | да | видео удалено или закрыто |
| любой другой 4xx на присланное, кроме строк ниже | `not_found` | да | не нашёл такой канал |
| на канале нет открытых видео (6.6) | — | да | короткий отчёт |
| `quotaExceeded`, `dailyLimitExceeded` | `quota` | нет | данные YouTube закончились — откроются через N ч; владельцу — уведомление; до полуночи по тихоокеанскому времени бот в Google не ходит (Л9) |
| `rateLimitExceeded`, 429 | `service_down` | нет | пауза 2 секунды и один повтор, затем «данные YouTube сейчас недоступны» |
| `keyInvalid`, `forbidden`, `accessNotConfigured`, `ipRefererBlocked` | `service_down` | нет | данные YouTube сейчас недоступны; владельцу — уведомление |
| 5xx, обрыв, срок запроса вышел | `service_down` | нет | один повтор, если до срока аудита больше 10 секунд, затем «данные YouTube сейчас недоступны» |
| ответ не той формы (нет ожидаемых полей) | `service_down` | нет | то же; владельцу — уведомление раз в сутки |
| срок аудита вышел в ожидании места (Л1) | `crowded` | нет | сейчас много проверок — пришлите ссылку через минуту |

## 6. Подсчёты

Все пороги — константы в одном файле `channel_audit/thresholds.py`, уточняются на прогоне (раздел 17).
«Сегодня» — дата сбора данных. Даты показываются по времени UTC+7; год — только если он не совпадает с годом сбора.

**6.0 Какие видео считаются.** Из собранных (5.1) отбрасываются: ещё не вышедшие и идущие сейчас эфиры
(`liveBroadcastContent` — `upcoming` или `live`); видео, которых нет в ответе `videos.list` (закрытые, удалённые).
Вид видео:

| Вид | Как определяем |
|---|---|
| эфир | есть `liveStreamingDetails`. По справке API этот объект есть у трансляций; если на разведке окажется, что он есть и у премьер, в тексте вид называется «эфиры (трансляции и премьеры)», иначе — «трансляции»: API их не различает, название следует его данным |
| короткое | не эфир, длительность до 3 минут включительно (`SHORT_MAX_SECONDS = 180`) |
| длинное | не эфир, длительность больше 3 минут |

«Короткое» — это длительность, а не «Shorts»: правила запрещают угадывать тип контента, а признака Shorts в API
нет. Поэтому в отчёте — «короткие (до 3 минут)». Видео без `statistics.viewCount` в «Отдачу» не идут, в ритм и
форматы — идут.

### 6.1 Ритм

- **Охват** — от самого раннего собранного видео до сегодня, но не больше 6 месяцев (`RHYTHM_DAYS = 182`). Обычно он
  равен полугоду. Меньше он бывает, если листание упёрлось в 200 видео (у канала 2–3 видео в день) или канал
  моложе полугода.
- Число видео за охват (все виды) и среднее в месяц: число ÷ месяцы охвата (не меньше 1 месяца), целым, половина —
  вверх; меньше 1 — «меньше одного в месяц». Охват — полгода: «31 видео за полгода, в среднем 5 в месяц»; меньше:
  «200 видео с 12 июля, в среднем 80 в месяц», «8 видео с 27 июля, в среднем 4 в месяц».
- Последнее видео: «сегодня», «вчера», «N дней назад» до 60 дней, дальше «N месяцев назад», от 24 месяцев — «N лет
  назад»; и дата.
- Перерывы дольше 45 дней (`GAP_DAYS = 45`), только внутри охвата и только между двумя собранными видео, плюс перерыв
  от последнего видео до сегодня:
  - перерыв до сегодня, если он дольше 45 дней, — всегда первым: «новых видео нет уже 67 дней»;
  - из прошлых — один, самый длинный: «перерыв 52 дня: с 2 мая по 23 июня»;
  - перерывов нет — «перерывов дольше 45 дней не было».
- За 6 месяцев видео не было — «за полгода новых видео не было» и строка о последнем видео; перерывы не
  показываются.

### 6.2 Отдача

- Считаются подходящие видео за последние 12 месяцев (`BASELINE_DAYS = 365`) из собранных — по трём группам:
  короткие, длинные, эфиры. Группы — отдельно: у коротких просмотры считаются с каждого запуска и повтора.
- Свежие видео не считаются: у них просмотры ещё набираются. Короткие — моложе 14 дней (`FRESH_DAYS_SHORT = 14`):
  им хватает первых дней. Длинные и эфиры — моложе 60 дней (`FRESH_DAYS_LONG = 60`): им просмотры месяцами
  приносят поиск и рекомендации.
- «Обычно» — медиана просмотров группы, если в ней не меньше 8 видео (`MIN_TYPICAL = 8`). Медиана чётного числа
  видео — среднее двух средних значений.
- «Последние 10» — медиана 10 самых новых видео группы, если в группе не меньше 15 видео (`MIN_TREND = 15`): иначе
  последние 10 — почти вся группа, и сравнение ничего не говорит. У длинных и эфиров — со словом «пока»: «последние
  10 пока — около 450».
- Лучшее за полгода — по одному в каждой группе, у которой есть «обычно» и хотя бы одно подходящее видео за 6
  месяцев: название ссылкой, точное число просмотров и «примерно в N раз больше обычного», если N не меньше 2
  (`BEST_RATIO_MIN = 2`) и «обычно» не меньше 1. N — отношение, округлённое до целого, половина — вверх. Иначе —
  только просмотры.
- Числа:
  - просмотры конкретного видео — точным числом API («8 437 просмотров»): руководство Google запрещает показывать
    число просмотров, отличное от числа API;
  - медианы — со словом «около»: меньше 100 — целым; до миллиона — две значащие цифры, половина — вверх («около
    1 200»); от миллиона — «около 1,2 млн» (en — «about 1.2M»).
- Ни одной строки не набралось — блока нет.

С 24.08.2026 YouTube считает просмотр с первого кадра для всех видео — новые видео могут выглядеть сильнее старых.
В отчёт это не выносится. На приёмке: если у длинных «последние 10» ниже «обычно» у 80 % прогнанных каналов и больше,
строка «последние 10» для длинных убирается (раздел 17).

- За 6 месяцев видео не было — блока нет.

### 6.5 Вывод

  1. темп сейчас — число видео за 60 дней ÷ 2, целым, половина — вверх: «Сейчас вы выкладываете 5 видео в месяц.»;
  2. Telegram:
     - нет нигде — «В описании канала и последних 10 видео нет ссылки на Telegram — зрителю, которому понравилось,
       некуда идти дальше.»;
     - только в описании канала — «Ссылка на Telegram есть только в описании канала — под видео, где её увидит
       зритель, её нет.»;

  видео снова начнут выходить — пришлите канал ещё раз.»

- Статус и отчёт — одно сообщение: `sendRichMessage` («Смотрю канал…»), потом `editMessageText` с `rich_message`.

### 7.6 Полоса

- Картинка 1600×400, как полоса канала: стекло шапки сайта, `~/` бирюзовым `#4DB6AC`, имя раздела светлым,
  JetBrains Mono. Делается генератором бота канала (`scripts/make_banner.py`, копия со шрифтами), лежит в
  `bot/assets/`: `banner_ru.png` — `~/аудит-канала`, `banner_en.png` — `~/channel-audit`.
- Загрузка — фоном при запуске, при неудаче — не чаще раза в час: `sendPhoto` владельцу без звука, `file_id` в kv
  с хэшем файла, сообщение сразу удаляется. Поменялась картинка — хэш другой, загрузится заново.
- Сообщения загрузку не ждут: пока `file_id` нет, шапка — моноширинная строка `>jw ~/аудит-канала_` (en —
  `>jw ~/channel-audit_`), как у чекера.
- Если отправка или правка статьи с полосой упала — одна повторная попытка той же статьи со строкой вместо полосы,
  `file_id` забывается; владельцу — `notify_banner` раз в сутки. Работа важнее оформления.
- Это делает обёртка над мессенджером в самом боте: ядро берёт мессенджер из данных диспетчера, правка ядра для
  этого не нужна.
- На разведке проверить одно: принимается ли `file_id` из `sendPhoto` фото-блоком в `sendRichMessage` и в правке.

## 10. Сеть и контейнер

**Решение: защиты домашней сети из чекера здесь нет** — ни своей таблицы nftables, ни `check_isolation.sh`.

Почему:

1. Защита чекера закрывает конкретную дыру: чекер сам соединяется с адресами, которые прислал человек, и без защиты
   его можно навести на роутер или соседний компьютер. У этого бота такого пути нет: присланное превращается в ID
   или имя по строгим правилам (В4), ссылки из описаний не открываются, а соединения идут только на постоянные
   адреса — `www.googleapis.com` и `api.telegram.org` (В9). `pageToken` для листания приходит от Google.
2. Остаётся общий риск любого контейнера — уязвимость в зависимости. Ограничения контейнера его не закрывают:
   домашняя сеть из контейнера доступна. Но риск не выше, чем у бота канала, который работает на том же сервере
   вообще без контейнера.
3. Своя таблица nftables — это служба systemd и проверка после каждой перезагрузки сервера и перезапуска Docker.
   Без угрозы, которую она закрывает, это обслуживание впустую.

Что есть вместо этого:

| № | Правило |
|---|---|
| С1 | Клиент YouTube собирает адрес только из постоянной части `https://www.googleapis.com/youtube/v3/` и имени метода; присланное попадает только в параметры запроса. Тест: при любом вводе запрос уходит на этот хост |
| С2 | Переадресации не проходим, прокси из окружения не берём (`trust_env=False`), у запросов сроки (5.3) |
| С3 | Своя сеть Docker с постоянной подсетью `172.30.98.0/24` и мостом `br-chaudit` (у чекера — `172.30.99.0/24`), без IPv6; `network_mode: host` запрещён |
| С4 | DNS контейнера — публичные серверы (1.1.1.1, 8.8.8.8), как у чекера |
| С5 | Контейнер как у чекера: не root — uid 10001, папка `data/` на сервере принадлежит 10001; файловая система только для чтения, кроме `data/` и `/tmp` (tmpfs); `cap_drop: ALL`; `no-new-privileges`; потолок памяти 256 МБ без свопа (`mem_limit` равен `memswap_limit`) — ожидается 100–150 МБ, потолок уточняется замером на приёмке; половина ядра; `pids_limit: 64`; логи Docker — 3 файла по 10 МБ |

## 12. База и учёт

SQLite `data/bot.db` на сервере, в папке бота; в git не попадает. Схема по версиям (`PRAGMA user_version`),
миграции — только добавляющие; база новее кода — бот не стартует; перед миграцией — копия `VACUUM INTO`. WAL,
`busy_timeout`, внешние ключи — как у чекера.

**users** — как у чекера (ядро): `user_id`, `lang`, `lang_manual`, `first_source`, `last_source`, `created_at`,
`last_seen_at`. Имена и юзернеймы не храним.

**audits**

| Поле | Что |
|---|---|
| `id` | ключ |
| `user_id` | кто запросил |
| `source` | `last_source` человека на момент аудита |
| `input_kind` | `handle`, `channel_id`, `user`, `legacy`, `video` |
| `channel_id`, `handle` | ID канала и @имя — данные YouTube, стираются через 20 дней |
| `status` | `running`, `done`, `failed`, `interrupted` |
| `error_code` | коды из 5.3 и отказов: `not_a_link`, `not_youtube`, `playlist`, `not_text`, `limit_user`, `limit_global`, `busy`, `crowded`… |
| `from_cache` | отчёт из кэша |
| `charged` | списана ли попытка (Л5) |
| `api_units` | сколько единиц квоты потратил аудит |
| `offered` | был ли вывод с предложением пакета (6.5) |
| `chat_id`, `message_id` | где живёт сообщение-отчёт |
| `created_at`, `finished_at` | время |

**kv** — `key`, `value`: `file_id` полос (7.6), время последних уведомлений владельцу, счётчик единиц за
тихоокеанские сутки.

- Срок данных YouTube — 20 дней (`API_DATA_DAYS = 20`): через 20 дней `channel_id` и `handle` обнуляются, строка
  аудита остаётся — это свои данные о событии. Уборка — при запуске и в суточной задаче прямо перед копией базы.
- Копии базы — раз в сутки, `VACUUM INTO` в `data/backups/`; хранятся 7 последних. Копии перед миграцией тоже
  удаляются через 7 дней — у чекера они остаются навсегда, здесь нельзя (Ю4).
- Отказы до сети — тоже строка в `audits`, с `error_code` и без списания. Текст «не ссылок» не храним.
- Метка — `t.me/jw_video_channel_audit_bot?start=<метка>`: латиница, цифры, `_`, `-`, до 64 знаков. Нет метки —
  `direct`; не подходит под правило — `invalid`. Предлагаемые метки: `channel`, `chat`, `site`, `fb`, `grp_danang`,
  `grp_women`, `grp_samui`, `post_<дата>`.
- Модуль учёта `core/stats.py` — единственный, кто пишет людей; аудиты — `channel_audit/audits.py`. Любая ошибка
  учёта — в лог, аудит идёт (Р16).
- `/stats` — за 7 и 30 дней, по меткам: новые люди; сколько людей получили отчёт; аудитов; из кэша; с выводом-
  предложением; отказов по кодам; единиц квоты за текущие сутки по тихоокеанскому времени и потолок. Внизу —
  напоминание: «Обсудить» считается по сообщениям в личке, откуда человек — `/channel`.

## 14. Сервер и выкладка

### 14.1 Один раз

### 14.2 Выкладка — `deploy/deploy.sh` с Мака

Как у чекера:

1. На Маке: всё закоммичено; `HEAD` совпадает с `origin/main`; `scripts/check_secrets.py --rev HEAD` чист. Иначе —
   стоп.
2. На сервере: `git status --porcelain` пуст, `git fetch`, `git checkout --detach <sha>`; в конце — сверка
   `git rev-parse HEAD` с Маком.
3. Нет `.env` — стоп. Скрипт `.env` не создаёт, не читает и не копирует.
4. `docker compose build`, `docker compose up -d`.
5. Ждать `healthy` до 60 секунд, показать `docker compose ps` и последние 30 строк лога.

- Откат — `deploy.sh <sha прошлого выпуска>`; миграции только добавляющие.
- Адрес сервера — его адрес в домашней сети; адрес, пользователь и путь — в `deploy/deploy.local.env` на Маке
  (в `.gitignore`), в репозитории — образец без значений. Из поездки владелец подставляет адрес в Tailscale вручную.

### 14.3 compose

- `name: jw_video_channel_audit_bot`; сервис `bot`; `restart: unless-stopped`; `env_file: .env`; папка `./data`
  подключается в `/app/data`; сеть, DNS и ограничения — раздел 10.
